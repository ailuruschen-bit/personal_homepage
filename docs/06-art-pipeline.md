# 06 Art pipeline

Every image in `public/assets/` is generated by the Python in `tools/art/`.
Nothing was exported from an image editor, and nothing in that directory should
be edited by hand. To change the picture, change the script.

```bash
pip install pillow numpy scipy
python3 tools/art/build.py            # writes into public/assets/
python3 tools/art/build.py /tmp/out   # or somewhere else, to compare
```

## Why generated rather than drawn

The scene needs a long city strip that loops seamlessly, three parallax layers
that agree with each other, and consistent lighting across all of them. Those
are easier to get right from code than by hand, and far easier to re-tune:
changing the neon palette, the density of lit windows or the strength of the
bloom is a constant, not a repaint.

The cost is that the scripts are the source of truth and the images are build
output. They are committed because the site must build without Python, but they
should always be regenerable.

## Output

| File          | Size     | Drawn by            | Used as                                    |

| `sky.webp`    | 960x540  | `far.build_sky`     | `.sky` background                          |
| `c1.webp`     | 1440x640 | `far.build_c1`      | far skyline, slowest parallax              |
| `c2.webp`     | 4320x640 | `city.build_c2`     | mid distance, the long looping strip       |
| `c3.webp`     | 1440x640 | `far.build_c3`      | trackside gear, fastest parallax           |
| `room.webp`   | 960x960  | `room.build_room`   | the carriage, with the window punched out  |
| `room-l.webp` | 240x960  | `room.build_room`   | wall revealed on the left when pulled back |
| `room-r.webp` | 240x960  | `room.build_room`   | same, right                                |
| `grain.png`   | 192x192  | `build.build_grain` | tiled film grain                           |

Output is **not** byte-reproducible across machines: the WebP encoder version
affects the bytes. The pixels are deterministic — every script seeds its own
`random.Random` — so regenerating on a different machine produces a visually
identical but differently compressed file. Do not treat a diff in
`public/assets/` as evidence that something changed.

## The canvas model (`px.py`)

The core idea: draw twice, light once.

Every `Cv` holds several parallel surfaces at 1x:

| Surface | Purpose                                                            |
| ------- | ------------------------------------------------------------------ |
| `im`    | **albedo** — the plain colour of each pixel, with alpha            |
| `em`    | **emission** — the colour of light each pixel emits                |
| `lt`    | **invisible light** — lights the surroundings but is never drawn   |
| `sh`    | **soft shadow** — multiplied into the lighting after a blur        |
| `fi`    | **fine layer** — drawn at output resolution, bypassing the upscale |

Drawing methods come in pairs. `rect`, `poly`, `ellipse` write albedo and
_clear_ the emission underneath, so a solid drawn over a light occludes it.
`lrect`, `lpx`, `lellipse` write both: a bright colour on the albedo and the
light colour on the emission canvas.

`light()` adds a glow with no visible source — the pool under a lamp, the
spill from a lit room. `shadow()` darkens a region without drawing anything.

### Lighting

`render()` composites everything in one pass:

```
final = albedo * (ambient + spill) + emission + bloom
```

where `spill` is the emission plus the invisible lights, blurred at two radii
and scaled, and `bloom` is the same blurred harder. Then:

- **Emitters do not pick up reflected light.** Without this, a wall of lit
  windows washes out to solid white.
- **Highlights are soft-compressed** above a knee of 0.72, preserving detail in
  bright areas instead of clipping.
- **Fog** can be applied per row, which is how the far layers get their
  atmospheric haze and their magenta stain from the city below.
- **Bloom spilling into transparent areas** becomes alpha, so glow extends past
  the silhouette of what emitted it.

`wrap_blur` can wrap horizontally, which is what keeps the glow continuous
across the seam of a looping strip.

## The 2x upscale and EPX

Art is drawn on a 1x grid and written out at 2x. `px.SCALE` controls this and
`build.py` sets it to 2.

The albedo is upscaled with **EPX / Scale2x**: a 2x nearest-neighbour expansion
that rounds a corner only when the neighbouring colours match exactly. Flat
areas and straight edges survive untouched; diagonals and curves lose half of
their stair-stepping. It keeps the result reading as pixel art while halving
the apparent pixel size.

Lighting, bloom and shadow are computed **after** the upscale, at the output
resolution, so glows and gradients are smooth rather than chunky.

### The fine layer

EPX has one failure mode that matters. A line that is meant to be straight but
sinks slowly with perspective becomes, at 1x, a one-pixel step every dozen or
so columns. EPX widens each step into a ramp, and the line reads as if it had
been bent.

`Cv.fline()` draws straight at the output resolution instead, with fractional
coordinates and thickness still counted in art pixels. The code rows on the
laptop screen and the printed rules on the ticket use it. The rule of thumb: if
a thin line is nearly horizontal and should look straight, it belongs on the
fine layer.

## The layers

`Cv.fpoly()` (and `Off.fpoly()`, `Off.frect()`) draw filled shapes on the same
layer, for objects whose outline is made of shallow diagonals: the laptop is
drawn there whole. The fine layer lies over all the 1x art, so an object moved
onto it has to move entirely, or its fine parts cover its 1x parts. Under a
fine shape the 1x emission is cleared and the shadow canvas set to unshadowed,
as under any solid.

### `street.py` + `city.py` — the mid distance (`c2.webp`)

The longest strip and the most machinery. `build_c2` assembles:

```
[overpass][neon district, 1440px][overpass][derelict blocks, 720px][overpass]
```

joined end to end so it loops. `street.neon_district` generates buildings with
brick or plaster facades, arcades, shopfronts (noodle bar, konbini, arcade,
bar, glass storefront, shutter, stairwell), vertical and horizontal signs, air
conditioners, balconies and cables. `city.ruin_district` generates the derelict
stretch: concrete frames with rooms laid open where the outer wall has fallen
away, boarded windows, graffiti, chain-link fences, burning barrels, wrecks,
and one bunker bar that is still lit.

Two passes are rendered and composited: a back row of taller buildings with
heavy fog, then the front row. Finally `wet_road` mirrors everything above the
kerb into the standing water, with per-row jitter for ripples.

Ambient light is modulated horizontally — the derelict stretch has no neon of
its own, so it is carried by brighter, more cyan moonlight.

### `far.py` — skyline, trackside, sky

`build_c1` draws two depth layers of towers with per-row fog, two
fully-lit neon towers, a suspension bridge, and three searchlight beams added
as a post-process.

`build_c3` is the foreground: catenary masts, cantilevers, contact wires with
droppers, signals and the viaduct parapet. Very dark, catching only a rim of
the city's light.

`build_sky` is the only layer that is not pixel-drawn: fractal noise thresholded
into three hard brightness bands, over a vertical gradient, with magenta rim
lighting on the underside of each cloud, then quantised to 64 colours.

### `room.py` — the carriage

Drawn on a 720x480 canvas covering scene x from -120 to 600, then cut into the
central 480 (`room.webp`) and the two 120-wide extensions.

The `Off` class wraps the canvas with an offset so every drawing call can be
written in scene coordinates directly. It can also carry a tag: while an
interactive object is drawn through `place()`, every solid or lit shape it
draws is recorded into that object's silhouette mask.

Sections: `shell` (ceiling, walls, floor, heater grille), `rack` (luggage and
the route map), `window` (frame, curtains, sill), `walls` (posters, neon tube,
wall lamp, control panel), `seat` (drawn twice, mirrored), `table` (laptop,
coffee, ticket, pen) and `extensions`.

Two things at the end are easy to miss:

- The lighting is finished with a set of `light()` calls that place the warm
  lamp, the cold window light, the screen glow and the floor lights.
- The window opening is punched out from `WINDOW`, one unit inside it so the
  frame overlaps `.win`, upscaled with the same EPX so its edge matches the
  artwork.

## Geometry comes from the art

Everything the page needs to know about where things are is defined once, at
the top of `room.py`, and generated from there by `build.py`:

| In `room.py` | What it is                                                     | Generated into                         |
| ------------ | -------------------------------------------------------------- | -------------------------------------- |
| `OBJECTS`    | each focusable object's corner, snap zone and light (relative) | `geometry.gen.ts`                      |
| silhouettes  | recorded while the object draws through `place()`              | its box, and `obj-<id>.webp`           |
| `WINDOW`     | the opening and its corner radius                              | `.win` in `geometry.gen.css`, the hole |
| `CAM_GAP`    | the gap in the blinds the camera flies through                 | `.cam`'s origin, `CAMERA`              |
| `GLOWS`      | the animated glows, two relative to their objects              | `.g-*` in `geometry.gen.css`           |
| `MARKS`      | the steam over the cup and the cursor on the screen            | `.steam`, `.cur` in `geometry.gen.css` |

`hotspots.ts` keeps only what is not geometry: the target section and the
object's name. A focused object lifts its own sprite, cut out along the
silhouette it drew, so its edge is the drawing's edge and nothing around it can
come with it.

Moving an object is a change to its `at` in `OBJECTS`. Its zone, light, sprite
and glow follow. The objects drawn before this existed keep their original
coordinates and are shifted by `place()`; new objects are drawn relative to
their own corner.

Two things the first objects did not need:

- **Depth.** `g.depth(z)` gives a canvas on which art written for the window
  wall is scaled about the vanishing point to stand `z` metres from the camera.
  The luggage on the racks is drawn this way, and an object marked `on_rack`
  has its zone and light scaled with it.
- **Something in front.** When part of the room crosses an object — the rack's
  rail across the briefcase's foot — that part is recorded as a second
  silhouette, `<id>/front`. The object's sprite is then cut from a second
  render without it, so it is whole, and the part in front becomes
  `obj-<id>-front.webp`, which the page keeps above the sprites and never
  moves. The object lifts behind it.

`npm run art:check` fails the build when the generated geometry, the hotspots
and the assets disagree, and `?debug=geometry` draws all of it over the scene.

### This used to be a source of bugs

Before stage 0 of [13](13-art-review.md), zones, lights and a polygon per
object were copied by hand into `hotspots.ts`, the window into four places, and
the glows into `scene.css`. An outline a pixel too generous lifted the wall
with the object. That is why none of it may be written by hand again.

## Keep in sync

- `px.SCALE` (set in `build.py`) and `.ly`'s `height` / `--tile` in
  `scene.css`: if a city layer changes pixel size, the CSS has to follow.
- Nothing positional — see [Geometry comes from the art](#geometry-comes-from-the-art).
  `npm run art:check` covers the city layers' sizes against `--tile` too.

## Value plan

After lighting, `value_plan()` in `room.py` grades the rendered picture by depth
plane, so that the planes separate in value (docs/13, L-06). The benches, the
table and the cup record silhouettes (`_bench`, `_table`, `_cup`) that are used
only here and never become sprites. The window wall, everything not in front of
it, takes the `far` gain and tint, which fades out below the table; the benches
take the `bench` gain. Tune the numbers in `VALUE_PLAN`, and judge the result on
`luma.png` from `npm run art:preview`.
